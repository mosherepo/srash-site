Licence renewals, data centre exits and consolidation programs all end in the same place: moving data without breaking the business. We assess every database honestly, move only what pays back and validate every row before cut-over.

Sound familiar?

  • An Oracle or SQL Server renewal is coming and finance wants to know what a move to PostgreSQL would really cost.
  • You are leaving a data centre or VMware and dozens of databases need a home on AWS, Azure or Google Cloud.

What we deliver

Scope is confirmed in writing in the assessment, with anything out of scope listed too.

  1. 01

    Portfolio assessment

    Every database scored on size, complexity, code, dependencies and business criticality, with a recommended target.

  2. 02

    Target design

    Aurora, RDS, AlloyDB, Cloud SQL, Spanner, Azure SQL or Azure Database for PostgreSQL, sized and secured with Terraform.

  3. 03

    Schema and code conversion

    Stored procedures, packages, triggers and data types converted and unit-tested, with tooling where it helps and engineers where it does not.

  4. 04

    Data movement

    Bulk load plus change data capture (AWS DMS, Datastream, Debezium or native replication) to keep downtime short.

  5. 05

    Validation

    Row counts, checksums and side-by-side query results compared automatically before each cut-over.

  6. 06

    Consolidation

    Fewer, larger, better-run instances with a clear owner, backup policy and patch routine.

Questions about this service

Straight answers on scope, fees and how we work. Anything else, ask us.

Ask a question

Do you always recommend leaving Oracle or SQL Server?

No. Some workloads depend on features that make a move expensive. The assessment shows the cost and payback for each database, and keeping some where they are is a valid outcome.

Can the migration be funded by the cloud provider?

Programs such as AWS MAP, Azure Migrate and Modernize and Google RaMP exist, but they are usually run through accredited partners. We are independent and do not claim access to them; we can work alongside a partner if you use one.

How long does a typical migration take?

A single application database usually takes weeks; a large estate is run in waves over months. The assessment gives a realistic plan.

Who owns the converted code?

You do. Everything goes into your repository.
